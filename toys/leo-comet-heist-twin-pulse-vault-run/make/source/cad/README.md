# CAD project map

`comet_heist.step.py` composes the deployed 24-occurrence assembly. `part_*.step.py` files are the nine unique printable families. `params.py` is the only dimensional authority; `validation.py` holds sealed-concept equations; `comet_heist_lib.py` builds geometry. `measure/check_fit.py`, `measure/check_spec.py`, `measure/check_support.py`, `measure/motion.json`, and `measure/verification-pipeline.md` are deterministic evidence. The magazine is one printed piece: a vertical web joins its body to the elevated end-slot tongue. The asymmetric bridge T-feet use a 6 mm slide beneath 2.5 mm integral tray shoulders with 0.25 mm vertical clearance.

The assembly preserves native occurrence labels but intentionally omits STEP display colours. OpenCascade serialized per-occurrence colour associations in process-dependent order, causing otherwise identical fresh assembly exports to change bytes. The physical single-material game does not rely on colour: Sun/Orbit ownership, READY/SPENT state, scores, and interfaces remain geometrically and tactually encoded.

Build from the workspace root with the Workshop Python and materialized CAD scripts. Use `CADGEN_COMPONENT_WORKERS=1` in the managed sandbox. Final verification uses `verify_project <this-directory> --assembly comet_heist.step.py --fresh --exports --motion-manifest measure/motion.json --bed 210x210x220 --nozzle 0.4`, followed on those fresh STLs by `measure/check_support.py --report measure/support-angle.json`.

The combined entry is view-only. Each `part_*` entry is printed at its authored bed datum. The corrected blade entry rotates its deployed X-axis trunnion vertical, producing a low-profile 37 x 14 x 14.7 mm print envelope instead of the rejected upright 14.7 x 14 x 37 mm envelope. Because its trunnion projects beyond both broad blade faces, the horizontal panel sits 3.35 mm above the bed and requires generated support. The 45-degree triangle screen requires generated support everywhere for the bridge, blade, both trays, and magazine, and no generated support for either comet, keeper, or seam key. This is an explicit print plan, not slicer output. No mesh is repaired downstream of source.

The product-root `assembled.stl` is the unmodified multi-body mesh exported from the valid deployed STEP. Validate it with `check_mesh --assembly`: all 23 shells are watertight and positive-volume; nine contact-seam edges are expected warnings because separately printable occurrences meet in assembly pose. It is not a one-piece print target and no repaired derivative is shipped.
