## Assembly STEP cause and repair

Fresh generation left every printable part STEP unchanged. Only `rainspell_dial.step` changed. A textual diff localized the change to reordered `MECHANICAL_DESIGN_GEOMETRIC_PRESENTATION_REPRESENTATION` blocks for the six optional component colors; `inspect diff` between the rejected and repaired STEP reported:

```text
topologyChanged=False, geometryChanged=False, bboxChanged=False, kindChanged=False
```

The product is specified for one ordinary rigid filament, so per-component presentation colors are not functional product data. `assemblies/product.py` now retains all native component labels and placements while omitting those optional color records.

## Residual generated-report cause and repair

The trusted gate invokes the CAD project from an isolated relative path named `project`. `check_thickness` records its input and report arguments verbatim in each generated Markdown report. The rejected proposal's six current thickness reports instead embedded `artifacts/make/r0001/product/cad/...`; therefore a host rebuild rewrote those declared report bytes even though their measurements and all geometry outputs were identical.

Two exact-path replays from independent fresh source copies used the host's relative invocation `verify_project project --fresh --exports --strict-fit`.
