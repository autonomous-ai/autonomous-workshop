# Motion presentation from declared poses

For a coupled mechanism, `motion_presentation.py` builds the manifest's
assembly entry once and uses the **same placed occurrences and pose-table
implementation as `check_motion`**. It exports the states itself. A separate
animation generator can drift from the motion being checked and is no longer
accepted as motion evidence by this version of the tool.

```bash
python "$CAD_SKILL_ROOT/scripts/motion_presentation.py" <project> --view iso
```

The tool reads `measure/motion.json` and covers every
`coupled_motion_collision` condition, including conditions inside assembly
sequences. Give each one a unique `id`. All animation states share one camera,
scale and world frame; source occurrence colors are retained. `--view` accepts
the named views from `render_review` or an `AZ,EL` pair.

The default selects eight increasing indices from each condition's table,
including its endpoints. For an indexed display or a nonuniform cycle, select
the exact meaningful indices from that same table:

```bash
python "$CAD_SKILL_ROOT/scripts/motion_presentation.py" <project> \
  --samples display-cycle=0,18,36,54,72,90,108,126 --view front
```

This example assumes a condition named `display-cycle` with at least 126
samples. The values are indices into its declared poses, not degrees. Repeat
`--samples` for other conditions as needed; unspecified conditions use
`--frames` (default 8). Each condition needs 8–48 distinct increasing indices,
and the complete presentation is bounded to 48 states. This renderer supports
motion tables of up to 10,000 steps. The existing collision gate still checks
the full declared cycle, not just the presented indices.

Named moving groups carry their descendants, preserving all ancestor
placements. Repeated labels need an unambiguous dotted path. Overlapping mover
selections, such as both a group and its child, are rejected because they
assign two motions to one occurrence. Rotation precedes translation, exactly
as it does in the motion checker.

Outputs are `snap/motion.gif` and canonical schema-v2
`snap/MOTION-EVIDENCE.json`. Each state is tessellated in memory and bound by
hash; no mesh reaches disk, because STEP is the only geometry format this
toolchain writes. Evidence binds the project Python sources, assembly entry,
motion manifest, condition/sample identities, camera and generated bytes. Final
validation reconstructs the states and GIF and rejects a mismatch even if the
evidence has been rehashed. Reconstruction uses the run's CAD and renderer
environment; keep those dependencies fixed. Existing frozen runs keep their
copied older tool and protocol.

For captions, read the actual identities and per-mover poses from the bound
state evidence:

```bash
python "$CAD_SKILL_ROOT/scripts/motion_presentation.py" <project> --describe-states
```

This read-only command prints JSON linking each state hash to its condition,
sample index, step count, rotation angle/axis and translation where present. It
uses the same pose-table arithmetic as the motion checker, including explicit
nonuniform tables and different motions for different parts. Use those values
directly when labeling a state. A state's position in the list is the ordinal of
its animation frame; it is neither a motion sample index nor an angle. The
command refuses stale source, motion-manifest or state bindings. It
does not construct CAD, reconcile state geometry, validate the animation, or
provide an independent review; the final validation below remains required.

After generation, obtain the existing independent motion review described by
the workflow's `references/motion-review-v1.md`. Its schema remains 1 and its
evidence hash must name the new evidence bytes. Generating a replacement movie
does not reuse an old critic's approval. `verify_project` and the Make finalizer
retain the required review before geometric reconciliation.

This establishes correspondence to the declared source model and poses.
It does not establish that those poses satisfy the Wish, that a mechanism
transmits force, that removable parts stay captured, or that it works after
printing. Drive, collision, retention, STEP and independent review requirements
remain separate; nothing here measures printability.
