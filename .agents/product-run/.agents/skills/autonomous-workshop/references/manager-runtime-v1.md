# Portable native execution v1

This frozen capability selects the native interface, not a different product
workflow. Every Manager retains the same stage artifacts, independent reviews,
finalizer, host gates, and effect boundary.

## One stage objective

Codex creates or continues its native Goal for the current stage subject.
Claude Code and Grok Build pursue that objective in their current native
session, using native task tracking if available. A Codex-specific Goal API
is not a prerequisite for those Managers. References to a stage "Goal" mean
this one objective with exact inputs, proof and stopping condition. Do not
search repeatedly for another runtime's tools or emulate Goals with Python,
a scheduler, or a fake state file.

`MANAGER.json.agent_directory` and `agent_suffix` identify the exact roster.
Use that materialized Inventor by id and its bound skills; do not assume a
`.codex` directory or launch another Manager CLI. Use the native file, shell,
image and specialist tools actually exposed by this runtime.

## Autonomous handoff

The immutable Wish and stage packet contain the task; no builder chat or
later operator instruction is needed. Resolve ordinary design choices through
the Wish, Taste and evidence. Save substantive work at the packet's paths as
you go so the next turn can resume from files instead of repeating research.

Read only the current stage reference. When ready, run its finalizer using
`$WORKSHOP_PYTHON` and return promptly after `agent-outcome.json` is written.
The host verifies the proposal and starts the next stage. Native completion
does not mean the host gate passed.

A missing tool, denied required operation, unavailable independent reviewer
or other concrete environment blocker must use the `need` finalizer with
`--status waiting` and an actionable reason. If Python itself cannot run,
report that failure plainly; do not repeatedly research or retry the same
operation. Never fabricate evidence to pass a gate.

Required reviews are exceptions to avoiding dependency on child work:
optional creative delegation must not block the critical path, but the final
blind critic and required manual editor remain mandatory. Give the blind
critic only exact images first, without inherited Wish/concept context where
the runtime exposes that control. Preserve its actual response before reveal.
If isolation cannot be established, use a need instead of claiming a blind
review. Changed images require the allowed new review and exact bindings.

Credentials and publication failures belong to the host. Do not seek secrets
in chat, change sealed content to fix authentication, or publish with agent
tools. A host `waiting` receipt is resumable, not a successful publication.
