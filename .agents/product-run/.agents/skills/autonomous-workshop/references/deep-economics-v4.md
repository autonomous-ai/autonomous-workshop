# Frozen Forge and Quest economics profile v4

This immutable marker freezes an evidence-shaped Codex profile for new Forge
and Quest runs. One persistent Codex thread remains bound to this complete
profile. Invent and Make use **high reasoning effort** because the production
comparison showed that medium Make was neither cheaper nor better: it consumed
more input tokens, produced a weaker mechanism proof, and falsely passed an
obviously generic blockout. Playtest and Release use **medium**.

Invent, Playtest, and Release compact automatically at 24,000 tokens. Make
compacts at the runtime's minimum supported 16,000 tokens so repeated CAD tool
cycles do not carry an unnecessarily large context. Normal turns have a
30-minute boundary. The first Make turn for each exact Make checkpoint has a
12-minute proof boundary; if it does not finalize, bounded recovery resumes the
same session, Goal, stage packet, and workspace with a normal turn. One
`workshop wish` or `workshop resume` invocation may launch at most eight native
turns across all stages.

The first Make deliverable is a persisted falsifier, never the complete
product. Create the smallest exact causal or kinematic proof and a neutral
volumetric blockout under the declared CAD project at
`review/early-proof/`. Run and inspect the exact numbers and pixels before
authoring the full part tree.

Self-review cannot pass the visual half of this boundary. Use one bounded
independent native visual critic:

1. Give the critic only the exact held and signature blockout images. Do not
   reveal the product name, Wish, concept, captions, or intended reading.
2. Record its unprompted object, volumetric form, obvious control, action, and
   spatial or causal relationship read.
3. Then reveal the exact Wish and sealed concept. Compare every explicit
   positive and negative held-form requirement and the anti-generic signature.
4. Treat any generic, plaque-like, board-like, box-like, container-like, or
   exposed-mechanism reading as failure. Repair the smallest proof, rerender,
   and repeat once at most before expanding final parts.

A passing report must bind the exact image hashes and remain under
`review/early-proof/`. It is model evidence, not a host aesthetic gate, and it
does not replace the later preflight-bound final signature review. Its purpose
is to reject a bad silhouette before expensive complete CAD.

When mechanism and blind visual proof both pass, reuse their exact parameters
and source. Persist the smallest complete product baseline immediately. Then
follow one funnel: generate and check that baseline, run all-printable
preflight, create final renders, perform the required final blind review, make
one focused repair at most, run one integrated final verifier, and invoke the
Make finalizer. Do not return to broad exploration or batch-compose an unseen
replacement product.

Use the exact CAD command shapes from the Make reference. Generate source
entries with `scripts/gen <entry.step.py> --write`; export STL from a generated
STEP with `scripts/export <part.step> --stl`; run iterative
`verify_project <cad-project> --print-preflight` without `--fresh`. Do not spend
a tool cycle rediscovering those interfaces or attempt generation against an
output `.step` file.

This profile does not waive Wish fidelity, Inventor Taste, full-tier CAD
checks, Quest Playtest, manual quality, or authenticated Factory publication.
Lower spend counts only when the exact product remains distinctive, desirable,
truthful, and gate-complete.
