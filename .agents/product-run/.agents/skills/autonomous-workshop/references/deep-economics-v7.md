# Frozen Forge and Quest economics profile v7

This immutable marker freezes a proof-batched Codex profile for new Forge and
Quest runs. One persistent Codex thread and one active stage Goal remain bound
to the complete profile. A turn boundary never advances a lifecycle stage or
weakens a gate.

Invent begins at high reasoning with a 20-minute boundary. If that turn times
out, bounded recovery uses medium reasoning for 10 minutes and must seal the
strongest viable source already developed instead of restarting selection,
research, exploration, or subagents.

Make begins with an eight-minute medium-reasoning proof turn. Its only job is
to persist the smallest exact causal or kinematic proof, neutral held/signature
blockout images, and one independent blind review under the declared CAD
project at `review/early-proof/`.

During this bounded proof phase, read the mandatory root, Workshop skill, and
current Make reference once in separate bounded reads. The broad CAD skill and
optional CAD references are deliberately deferred until the proof marker
exists; the host already supplies the complete proof interface. Do not invoke
help, enumerate skills, or repeat stable reads.

The proof source defines exactly one module-scope `gen_step()` and returns its
build123d shape. The host binds `XDG_CACHE_HOME` to a private writable directory
inside the run, so no user cache probe, cache bootstrap, or environment repair
is needed. Generate, export, and render use the exact `$WORKSHOP_PYTHON`.

Before running the CAD batch, spawn one independent blind critic without the
Wish or concept. Give it only the exact held/signature paths and ask it to wait
for those files, then record its unprompted object, volumetric form, obvious
control, action, and spatial or causal relationship read. The root Manager
compares that read against every positive and negative Wish requirement; a
second revealed child turn is unnecessary.

Run generate, export, and render together in one foreground tool call rather
than paying an agent reasoning cycle between deterministic commands:

```bash
"$WORKSHOP_PYTHON" .agents/skills/cad/scripts/gen <entry.step.py> --write
"$WORKSHOP_PYTHON" .agents/skills/cad/scripts/export <entry.step> --stl
"$WORKSHOP_PYTHON" .agents/skills/cad/scripts/render_product <entry.stl> \
  -o <cad-project>/review/early-proof/held.png \
  --motion-sheet <cad-project>/review/early-proof/signature.png \
  --motion-angles=-12,0,12
```

If the blind read is generic, plaque-like, box-like, container-like,
board-like, or exposes the mechanism instead of the magic, repair once and
rerun the same batch. Do not expand the complete part tree before this proof is
legible.

When proof and review are durable, write the exact checkpoint-bound
`.make-proof-ready.json` described by the host prompt. The launcher treats it
only as a voluntary native-turn completion marker. It ends the proof turn and
resumes the same Make Goal at high reasoning with a normal 30-minute turn. It
is not a stage proposal, aesthetic gate, lifecycle transition, or evidence
waiver. Only `agent-outcome.json` from the real Make finalizer can propose a
stage transition.

After the proof turn, load the broad CAD skill and only the references needed
for the exact final product. High-reasoning Make reuses the passing parameters
and source, persists the smallest complete product baseline immediately, and
follows one funnel: generate and inspect the baseline, run all-printable
preflight, create final renders, perform the required final hash-bound blind
review, make one focused repair at most, run one integrated final verifier, and
invoke the Make finalizer. Do not return to broad exploration or tool-interface
discovery.

Every stage compacts at 24,000 tokens. Playtest and Release use medium
reasoning and normal 30-minute turns. One `workshop wish` or `workshop resume`
invocation may launch at most eight native turns across all stages.

After proof, iterative preflight is `"$WORKSHOP_PYTHON"
.agents/skills/cad/scripts/verify_project <cad-project> --print-preflight`
without `--fresh`. The trusted host owns the authoritative isolated fresh
rebuild.

This profile does not waive Wish fidelity, Inventor Taste, full-tier CAD
checks, Quest Playtest, manual quality, authenticated Factory publication, or
GitHub snapshot integrity. Lower spend counts only when the exact product is
distinctive, desirable, truthful, gate-complete, publicly verified, and
archived.
