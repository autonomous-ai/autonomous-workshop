# Make for Forge and Quest

Read this once in a Forge or Quest Make, beside `make.md`. Spark never needs
it. Where it differs from `make.md`, this file wins for Forge and Quest.

## Critical path

Trust the sealed Invent contract. Do not repeat research, roster comparison,
or broad concept exploration. Make never edits sealed Invent bytes, so the
styling revision `make.md` allows before the final review does not apply;
only an exact build-blocking contradiction may use the optional
[`make-invent-revision-v1.md`](make-invent-revision-v1.md) route.

## Frozen economics and proof turns

The host freezes one versioned economics profile for the whole session. Spend
high reasoning where it changes the concept and exact final product. Under
the deep profiles Invent begins with a 20-minute high-reasoning turn and gets
one decisive 10-minute medium recovery when needed. Make begins with one
16-minute medium proof runway and resumes the same Goal at high reasoning as
soon as its exact proof-ready marker exists; later turns keep 60 minutes.
Token-budget runs have no Workshop wall-clock, native-turn or lifecycle-round
cap; Make's own checks and review allowance still apply. A later explicit
operator resume with valid proof continues normal final-Make recovery without
replaying the source handoff. Treat every profile as a focus constraint, not
permission to make a generic product or skip proof.

In Make, the first persisted deliverable is the smallest exact causal or
kinematic proof plus neutral held/signature blockout renders under
`<cad-project>/review/early-proof/`. Inspect it before authoring the complete
part tree or detailed final geometry. Batch mandatory reads, author source as
the next durable action, and use root inspection for this cheap direction
check. If the early proof is expensive or ambiguous, simplify the mechanism
while preserving the signature magic. A proof turn's host prompt is exact:
follow it literally. It names the commands, the files to persist and the
`.make-proof-ready.json` marker, which ends only that native turn and never
advances Make. The resumed turn reuses the passing proof rather than
restarting, and only then loads the broad CAD skill.

During a frozen deep-v8 or deep-v9 proof turn, create or continue the Make
Goal immediately, then inspect the required stable instructions, stage
packet, and sealed concept in one bounded batch rather than separate tool
calls. Write source and its parent directories in the next file edit before
optional reading or help discovery. The broad CAD skill is deliberately not
applicable until the proof marker exists. Do not inspect an empty product
tree, create an empty directory as separate work, or spawn an early critic.
Persist exact mechanism/relationship evidence, neutral held/signature
blockout images, and one compact root visual finding under
`<cad-project>/review/early-proof/`. Replace the bracketed paths from
`STAGE.json`; do not invoke help to rediscover this interface or configure a
cache. The host binds a private writable `XDG_CACHE_HOME`. The proof entry
defines exactly one module-scope `gen_step()` and returns the build123d
shape. Generate and render it in one foreground tool call:

```bash
"$WORKSHOP_PYTHON" .agents/skills/cad/scripts/gen <entry.step.py> --write
"$WORKSHOP_PYTHON" .agents/skills/cad/scripts/render_product <entry.step> \
  -o <cad-project>/review/early-proof/held.png \
  --motion-sheet <cad-project>/review/early-proof/signature.png \
  --motion-angles=-12,0,12
```

The canonical independent blind critic remains mandatory during final Make.

## Baseline and repair

Write the smallest viable parametric baseline with exactly one non-part
combined `*.step.py` entry and one `part_<role>.step.py` per printable part.
Forge and Quest keep this whole-product baseline sequence; the Spark
component-first steps, Component Workers and Component Reviewers of
`make.md` do not apply. Iterate with assembly `make_round` rounds and
`--record-visual`, then the blind review and the final verifier as `make.md`
describes. For final Make, allow three focused repair-and-rereview cycles
after the initial independent review (four reviews total), within the run's
remaining budget; this supersedes the older one-repair wording in the
economics references.

## Host verification

The host reruns the integrated CAD verifier in an isolated fresh rebuild
before it accepts a Forge or Quest Make, in the tier the product declares:
`full-with-thickness` with `print_ready_claim: true`, or
`digitally-verified-not-print-ready` with `false`. A claim the sealed project
cannot reproduce is refused rather than downgraded. Release then asks for
print-ready CAD evidence again. Quest Playtest owns its separate evidence.
