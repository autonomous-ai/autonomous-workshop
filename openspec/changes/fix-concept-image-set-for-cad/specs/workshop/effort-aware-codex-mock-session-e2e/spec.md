## ADDED Requirements

### Requirement: Real Codex acceptance discovers and finalizes the fixed role contract

The opt-in authenticated Forge and Quest acceptance tier SHALL demonstrate that the persistent native session discovers the fixed-view capability from materialized production context, authors only the consolidated Invent source and required instruction document, covers exactly the host-derived roles, and invokes the normal finalizer without a duplicated schema overlay. Host effect doubles SHALL render and seal the fixed set only after the native Invent turn exits, and the same session SHALL resume at Make.

#### Scenario: Real Codex authors a fixed multipart plan
- **WHEN** a marked acceptance Wish produces multiple stable components
- **THEN** Codex supplies one instruction for each of front, top, bottom, exploded, and every component
- **AND** production host processing derives, renders, and seals exactly that fixed inventory

#### Scenario: Native output retains adaptive role selection
- **WHEN** Codex authors primary-form, signature-experience, alternate, or optional role selection under the fixed marker
- **THEN** the finalizer rejects the instruction document and no image effect runs

### Requirement: Acceptance evidence reports fixed-view usability narrowly

The acceptance report SHALL bind the capability version, authored-input hashes, component count, exact `4 + component_count` role count, finalizer rejections, effect wait/reconciliation behavior, same-session Make transition, and complete production gate result. It MUST NOT claim that structural success proves image quality, CAD reconstructability, printability, or physical performance.

#### Scenario: Fixed-view acceptance completes
- **WHEN** the route reaches its terminal result
- **THEN** the report distinguishes exact protocol usability from subjective image and product quality
