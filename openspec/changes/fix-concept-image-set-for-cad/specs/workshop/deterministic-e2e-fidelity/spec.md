## ADDED Requirements

### Requirement: Deterministic routes prove the fixed Concept image boundary

Marked Forge and Quest deterministic end-to-end coverage SHALL author the production fixed-view instruction document, invoke the materialized Invent finalizer, let production code derive and validate the exact `4 + component_count` role set, execute every role through deterministic provider transports in dependency order, seal exact returned bytes, and pass the resulting Concept identity to Make. Fixtures MUST NOT write derived roles, effect intents, receipts, sealed Concepts, gates, or checkpoints directly.

#### Scenario: Fixed-view Forge route succeeds
- **WHEN** a deterministic Forge run declares two stable components
- **THEN** production processing creates exactly six ordered Concept effects and seals their exact results before resuming the same native session at Make

#### Scenario: An adaptive or extra role is authored
- **WHEN** a new fixed-view fixture includes a non-derived role or omits a component role
- **THEN** production validation fails before any provider transport is called

### Requirement: Compatibility and failure paths remain end-to-end visible

The deterministic route matrix SHALL prove frozen v1 fixed-role and v2 adaptive checkpoints remain resumable, while new fixed-view runs cover component-limit rejection, unsafe or duplicate role paths, missing predecessors, partial completion, ambiguous effects, reconciliation, changed source, Invent revision, exact sealing, Make component equality, and Concept-pixel exclusion.

#### Scenario: Adaptive v2 fixture runs beside fixed-view coverage
- **WHEN** the installed host executes one frozen adaptive run and one new fixed-view run
- **THEN** each run uses only its checkpoint-bound schema, roles, prompt protocol, and effect identities
