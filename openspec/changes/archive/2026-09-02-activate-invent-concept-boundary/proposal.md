## Why

Forge and Quest currently stop Invent after sealing a compact `NativeInvented` record even though the restored Concept contracts can express the researched physical brief, component plan, visual instructions, and exact rendered design that Make needs. Because those contracts are deliberately dormant, no product run authors, renders, seals, or consumes them; activating them inside Invent makes the design commitment real without reviving a separate Concept stage.

## What Changes

- Version new Forge and Quest runs with an active compound Invent boundary that selects the Inventor, seals `NativeInvented`, authors a complete pre-render Concept source, and returns from the same Invent Goal and native turn.
- Extend the Invent finalizer and host gate so pre-render Concept source is a mandatory, exact, structurally valid part of a ready Invent proposal; invalid authored bytes return through the existing bounded Invent rejection path.
- Add a credential-isolated, authorized, durable Concept image effect: the host records intent before transmission, renders every required role in deterministic dependency order, reconciles provider operations and receipts, seals exact returned bytes, and represents incomplete or ambiguous outcomes as an Invent wait rather than retrying blindly.
- Seal the completed Concept as part of the accepted Invent checkpoint and bind its exact identity, derived Wish, brief, component set, source tree, images, and effect receipt into the following Make packet and `NativeMade` contract.
- Require Forge/Quest Make to rehash the standing Concept, preserve its numerical brief as the physical authority, match its declared component set exactly, and keep Concept pixels out of the product tree. A proven build-blocking Concept contradiction continues to use the existing Make-to-Invent revision edge and shared revision budget.
- Keep the executable topology unchanged: Forge remains `Wish -> Invent -> Make -> Release`, Quest remains `Wish -> Invent -> Make -> Playtest -> Release`, and no Concept stage, Goal, turn, checkpoint, transition, or Concept-only wait is introduced.
- Leave Spark and every frozen older run on their existing immutable protocols. Spark receives no Concept requirement in this change because it has no Invent stage; a later independently versioned change may activate the same sub-boundary inside folded Spark Make.
- Update deterministic and real-Codex acceptance traces, product-run instructions, lifecycle documentation, packaging, wait/resume, tamper, rejection, and effect-reconciliation coverage together with activation.
- Expose a complete field-by-field, agent-facing canonical skeleton for every
  Concept-authored JSON file, including nested records, role dependencies,
  descriptor timing, and canonical hash derivation, so Invent does not need to
  reverse-engineer accepted input structure from finalizer implementation.

## Capabilities

### New Capabilities

- `workshop/invent-concept-boundary`: Defines the versioned compound Forge/Quest Invent protocol that authors, validates, renders, seals, and checkpoints one Concept without adding a lifecycle stage.
- `workshop/concept-image-effects`: Defines authorization, intent, idempotency, provider-operation reconciliation, receipt binding, unknown outcomes, and exact-byte sealing for host-owned Concept image generation.

### Modified Capabilities

- `workshop/concept-stage`: Replaces dormant-only behavior for newly marked Forge/Quest runs with an active Invent sub-boundary while continuing to forbid a standalone Concept stage.
- `workshop/concept-images`: Makes every validated image role mandatory in a host-sealed Forge/Quest Invent result and preserves the narrow non-evidentiary claim of those images.
- `workshop/concept-image-integration`: Activates a provider only through the new durable host-effect boundary and defines credential, origin, ordering, reconciliation, and failure behavior.
- `workshop/make-concept-adherence`: Makes the standing Concept a mandatory exact input and output binding for newly marked Forge/Quest Make attempts.
- `workshop/wish-research`: Moves Concept research and physical breakdown authoring into the existing Forge/Quest Invent Goal and defines truthful waiting when required research cannot be completed.
- `workshop/deterministic-e2e-fidelity`: Extends exact route traces to cover the compound Invent artifacts, host image effect, Make binding, tamper refusal, and reconciliation paths without changing stage order.
- `workshop/effort-aware-codex-mock-session-e2e`: Requires the real persistent Codex session acceptance tier to author and finalize the active Concept source during Forge/Quest Invent and resume through host effect waits.

## Impact

- Depends on the completed `restore-dormant-concept-contracts` change and its route-aware schema-v2 pre-render/sealed contracts being integrated first.
- Affects `src/workshop/workflow/`, Invent and Make contracts/gates, runtime effect storage, a credential-bearing Concept image integration, the materialized product-run finalizer and Invent/Make instructions, checkpoint capability markers, package data, public archive preservation, and lifecycle documentation.
- Adds a configured image-generation provider dependency at the host adapter boundary, but no provider credential or private effect state enters the native Codex subprocess or public artifacts.
- New Forge/Quest checkpoints and contracts are intentionally incompatible with older frozen finalizers; compatibility is selected from immutable materialized capability bytes rather than inferred from installed code.
