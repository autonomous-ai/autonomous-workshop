A component round builds its Component once for its checks, and they read
that B-rep at the same time. Each of a round's seven steps used to load the
same `part_<id>.step.py` and call `gen_step()` again, so a spine-housing
round of Broken God attempt 18 spent 15-19 minutes rebuilding for checks
that take seconds. Measured on copies of that run: spine-housing 130 s
(was about 780 s), wing 72-112 s (was 967 s).

Beside `gen --write`, a round runs `cad/scripts/brepbundle.py build` once per
part: it builds the source as a print gate does and keeps it as a native
B-rep bundle (`BinTools`: doubles, tolerances, face types and mesh as built,
plus every build123d node's label, colour and children and the
print-details feature tags). Reading a direction normalizes it again, so a
line can come back one unit in the last place off and the read B-rep can
hash apart from the build; the bundle records both identities and the
largest sampled drift, and is written only when every node reads back with
the same topology, types, orientations, label, colour and class, within
1e-9 mm, and two reads agree. make_round uses it only when its build is the
identity `gen` reported; the build's identity stays the round's.

make_round points `check_thickness`, `check_overhang`, every `check_envelope`
and both renders (the print stance and the Display Pose) at the bundle
through the environment and runs them in parallel (`MAKE_ROUND_JOBS`,
default up to 8; `1` runs them in order). The reproduction build of #102 and
one build per placed instance (not one per envelope) run beside `gen`.
Placement still goes through the entry's `assembly_pose`. Each check
recomputes the identity it read, refuses a bundle that does not read back as
recorded, and prints it; the round records them all in `summary.json` under
`brep`. Bundles live in cadgen's derived cache (`__cadgen__/round-brep/`,
latest round per scope only), so they are never sealed or published.
Command lines and report formats are unchanged, and a round that fails its
checks is still not rendered. On spine-housing every verdict, report and
image matched a rebuild byte for byte; on the wing every verdict matched,
the thickness gate drew 277560 samples where a rebuild drew 277725, and 1-8
pixels per render moved by 1-2 of 255.

Assembly rounds build their parts in parallel and gate them from their
bundles; interface rounds build their Components in parallel. An entry with
`gen_print_union()`, a gate outside a round (`verify_project`, the host's
print-ready rerun), and a round whose `gen` reused a current build keep
building from source. Frozen runs keep their materialized tool bytes.
