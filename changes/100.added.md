- `workshop resume <wish-id> --amend-contract CONTRACT.md` answers a Contract
  Contradiction need with the owner's amended contract instead of a new
  attempt (issue #100, amending ADR 0085). The host diffs the file against
  the contract the run reads now and records only changed requirement text,
  Interface text and prose as an Owner Contract Amendment, by hash, in the
  run root's `CONTRACT-AMENDMENTS.json` and its own host-correction ledger.
  It refuses a changed reference, camera, geometry, requirement id or scope,
  Interface id, kind or Components, or schema, and keeps the run's sealed
  name line, `WISH.json` and images.
- `make_round` and the Make finalizer read the owner's rows after every
  applied in-run amendment; only Components whose own rows changed unlock,
  and in-run amendments close. Make acceptance seals the owner amendments
  beside the in-run ones and refuses an in-run amendment proposed after
  them; `workshop status` prints each one.
- A run materialized before this change is refused with a clear message and
  nothing is written: its frozen `make_round` and finalizer would keep
  reading the sealed rows.
- `build-a-toy`: after an invisible root fix to a run stopped on a
  contradiction, `ledger.py next` prints `resume-amendment` and the loop
  resumes that run with the owner amendment, relaunching only when the run
  refuses it (`resume: refused`).
