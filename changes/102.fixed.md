- One unchanged Component source now builds the same B-rep every time
  (issue #102, amending ADR 0073). build123d asks OCCT for a parallel
  Boolean before every fuse, cut and section, and near-tolerance contacts
  then settle differently from run to run. In Broken God attempt 18 the
  unchanged `part_spine-housing.step.py` was accepted at one identity and
  rebuilt at another, so assembly marked it stale; a copy of that source
  built 8 times at once gave `567d16…` with a rivet refused at `:313` once
  and `2f8e11…` seven times. Every loader in the Make toolchain that runs a
  `gen_step()` source (`gen` and the rest of cadgen, the print gates,
  `render_review`, `render_product`, `check_mount`, `check_motion`, the
  `cadcache` and motion workers, image-to-cad's `render_views`) now calls
  `cadgen.booleans.serial_booleans()` first, which keeps every OCCT Boolean
  serial whatever build123d asks for. With it all 8 builds gave `2f8e11…`
  and no refusal. A Component file needs no wrapper of its own.
- A component round now builds its source a second time in its own process
  (`make-round/scripts/reproduce_build`, logged as `reproduce-<role>.log`)
  and fails the build as `not reproducible`, with both identities
  (`build.identities`, `build.reproducible: false`), when the two builds
  differ in identity or only one refuses a detail. The failure surfaces in
  the component round, before the review, instead of at assembly. It runs
  only when `gen` reported a fresh identity.
- Measured cost of serial Booleans on the Broken God Components (one build
  at a time, one process each, shared 64-core host at load 15-22): spine-housing
  125.6 s parallel / 104.4 s serial (mean of 2), wing#1 55.2 / 51.7 (mean of
  2), chest-cage 50.3 / 44.1 (mean of 2), wing#2 47.3 / 44.2, gear-base
  29.6 / 27.2, arm-left 22.5 / 18.8, legs-pelvis 14.1 / 10.2, arm-right
  12.6 / 8.8, heart-core 11.7 / 10.9, crest-helm 9.6 / 8.8, gear-staff
  9.4 / 7.2. All eleven builds: 388 s parallel, 336 s serial, 13% faster,
  and each Component gave the same identity either way. The component
  round's second build adds one build per round until #101 runs it beside
  the round's other checks.
- `cadcache` keys now name serial Booleans, so a body cached from a
  parallel build is rebuilt once. Identities sealed from parallel builds may
  miss a Correction Run's comparison and rebuild; never a false match.
  Frozen runs keep their materialized tool bytes.
